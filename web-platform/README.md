# OpenRP Framework web platform

The public server template, UCP and ACP run together in **web/** (Next.js).
**samp-agent/** controls the game process, RCON, logs and model files. **api/** is
an optional Fastify health-endpoint scaffold. **livekit/** is an optional external
voice-service template, disabled by default.

See [SETUP.md](../SETUP.md) for Windows, Linux and EasyPanel. These are ordinary
Node.js services; Docker is optional. Linux with EasyPanel is recommended.

Import the root clean database schema first. It includes all web tables and no
administrator or player data. Copy web/.env.example to .env.local, set DATABASE_URL
and AUTH_SECRET, then run npm ci, npm run db:generate and npm run admin:create --
--name Admin_User --email owner@example.com. The one-time bootstrap assigns level 8,
prints a random password once, and refuses to run if an administrator already exists.

Existing MariaDB installations can apply web/prisma/sql/framework-web.sql after a
backup. Regenerate Prisma and restart web. Never use prisma db push on the full
game database: the web ORM intentionally covers only the fields it needs.

Discord, voice and custom skins are opt-in. Email 2FA requires SMTP and a verified
email; codes expire, have limited attempts and cannot be replayed. Password changes
revoke existing web sessions. Custom skins require both CUSTOM_SKINS_ENABLED=true
and FEATURE_CUSTOM_SKINS=1 in Pawn. Upload pairs through the agent and fully restart
the game before using them. No custom models, channels or groups are seeded.

web/WEBSITE.md explains public-site configuration. environment-variables.json lists
names without values. database-compatibility.json is regenerated by npm run db:check.

## Live game configuration

ACP → Configuration uses shared validation and transactions in shared/runtime-config.
Keep shared/ beside web/ during builds and deployment. Manager-level saves have
revision conflicts, audit/restore history and game acknowledgement. Connected
entities include armory types, lockers, weapons and stock faction uniforms. Use the
in-game editors for ATMs, repair points, properties, vehicles and dealerships;
their existing native validation/reload protections remain. Journal triggers capture older editors and game commands too.

For a fresh installation, import the root `database/schema.sql` into an empty
database with ALTER, TRIGGER, CREATE ROUTINE and ALTER ROUTINE privileges. It already contains the runtime
tables, defaults and journals; no numbered upgrade steps are needed. Keep the
trigger definer account available. See ../RUNTIME-CONFIGURATION-PROGRESS.md for remaining
entity adapters, and ../tools/runtime-config/README.md for contributor checks.
